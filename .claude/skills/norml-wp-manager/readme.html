Connect once, let the AI map your WordPress site, then manage the surfaces it can actually reach in plain language.

For: WordPress site owners and content teamsActs on: one connected WordPress site through RESTAPI · content and administration
The problem

Small WordPress changes pile up when the person who knows what should change is not comfortable making it in wp-admin.

Every site exposes a different mix of content, fields, plugins, and permissions. The Copilot maps this site first and writes the real boundary into capabilities.md instead of guessing.

API, not server access
This is the content and administration Copilot. Code, WP-CLI, SSH, GitHub, database work, and deployment belong to Norml WordPress Copilot Advanced.
What it does

The generated capability map is specific to the connected role and current site.

Edit and publish contentREST-gated
Pages, posts, media, terms, schedules, and exposed custom content.
Map the site oncefirst run
Records identity, site basics, content model, plugins, theme, and REST surface.
Write capabilities.mdvisible contract
Explains what this login can read, create, update, and delete.
Remember safelylocal dossier
Keeps site notes and a change log outside the skill package.
Change code or server stateAdvanced
Routes theme, plugin, SSH, database, GitHub, and deployment work onward.

Boundary
No theme or plugin code, SSH, WP-CLI, SQL, GitHub, or deployment.
No claim that a field is editable unless the live REST capability check supports it.
Opaque page-builder canvas data stays out of scope unless a supported API exposes it safely.
Broad, destructive, access, and site-wide writes require confirmation.

When REST is the wrong layer, it points to wp-admin or Norml WordPress Copilot Advanced.
